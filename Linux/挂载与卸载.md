## 一、概念与辨析

### 1.1 四个词，必须分开

| 说法 | 准确含义 |
| --- | --- |
| 盘 | 物理设备，如 `/dev/sdc`（整块盘） |
| 分区 | 盘上划分出的逻辑单元，如 `/dev/sdc1`、`/dev/nvme0n1p1`；**常规挂载对象** |
| 文件系统 | 分区（或镜像、内存区）上格式化出的结构，如 ext4、NTFS、tmpfs；**挂载绑定的是文件系统，不是"盘"** |
| 挂载点 | **Linux 目录树中的某个目录**，如 `/mnt/data`、`/home/<用户名>/mnt/data`。与 Windows 盘符无关，不能指向 Windows 路径 |

### 1.2 挂什么：盘、分区、还是整个文件系统

一块磁盘被分区工具划分后，**每个分区各自独立格式化、各自独立挂载**。挂载的单位始终是"分区上的那个文件系统"，不是"这块盘"。

**各类设备的命名规则**：

| 设备类型 | 盘 | 分区 | 说明 |
| --- | --- | --- | --- |
| SATA/SAS/USB 硬盘、SSD | `/dev/sda`、`/dev/sdb`、`/dev/sdc` | `/dev/sda1`、`/dev/sda2`、`/dev/sdc1` | 字母按内核探测顺序分配，**同一块盘换接口或加减盘后字母可能变** |
| NVMe 固态（M.2） | `/dev/nvme0n1` | `/dev/nvme0n1p1`、`/dev/nvme0n1p2` | `n1` 是控制器编号，`p1` 是分区号 |
| 虚拟盘（VHDX、virtio） | `/dev/vda` | `/dev/vda1` | 虚拟机、虚拟磁盘容器 |
| 内存盘、loop | 无实体盘 | — | 直接以 `tmpfs`、`/dev/loopN` 形式存在 |

**因此有两条规则**：

1. **常规挂载对象是分区**，如 `mount /dev/sdc1 /mnt/data`；
2. **例外**：设备整体格式化、未做分区表时，挂载设备本身（典型是整盘格式化的 U 盘、软盘镜像）。

**一个多盘多分区的实例**（两块 SSD + 一块机械硬盘的常见布局）：

```
/dev/nvme0n1        系统 SSD 1
├── /dev/nvme0n1p1  EFI 系统分区      → 挂 /boot/efi，类型 vfat
├── /dev/nvme0n1p2  交换分区          → 由 swap 使用，不挂载点
└── /dev/nvme0n1p3  Linux 根分区       → 挂 /，类型 ext4

/dev/sda            系统 SSD 2（例如另一套系统）
├── /dev/sda1       Windows 保留区     → 不挂载
└── /dev/sda3       NTFS 数据分区      → 挂 /mnt/winc，类型 ntfs-3g

/dev/sdc            机械硬盘
└── /dev/sdc1       数据分区           → 挂 /mnt/data，类型 ntfs-3g
```

同一台机器上，分区按"所属设备名 + 序号"区分，序号从 1 开始；NVMe 带字母 `p`，SATA/USB 不带。判断依据不是记忆，而是 `lsblk -f` 的实际输出。

## 二、为什么要挂载

### 2.1 现象对比：Windows 开箱可用，Linux 必须先挂

**Windows**：插入 U 盘，系统自动分配盘符（`F:`），资源管理器里立刻出现一个可点开的图标。用户看到的是**盘符**——卷本身就是可访问的入口，不需要任何手动动作。文件夹同理：`C:\Users\xxx` 打开就能用。

**Linux**：插入 U 盘，`lsblk` 能看到 `/dev/sdb1`，但**没有任何路径能访问里面的文件**。必须执行挂载，把文件系统接到某个目录上，那个目录才成为它的入口。

**那为什么 Linux 桌面里也有插上就能点开的盘？** 因为**桌面环境代为挂载**。GNOME/Deepin 的自动挂载服务（udisks2）检测到介质后，自动挂到 `/media/<用户名>/<卷标>` 下。同理，开机时 fstab 里标了 `auto` 的分区（`/`、`/boot/efi` 等）已在启动过程中挂好，所以开机后看起来"本来就在那儿"。

**结论**：Linux 里"能看到目录"这件事，**从来都是已经被挂载的结果**，不是文件系统自带的能力。差别只在于：Windows 由内核统一分配盘符；Linux 由 fstab、udisks2 或手工 `mount` 完成——谁挂、挂在哪、什么时候挂，都是可配置、可撤销的。

|   | Windows | Linux |
| --- | --- | --- |
| 卷标识 | 盘符 `C:` `D:` | 设备名 `/dev/sda1`、`UUID=` |
| 访问入口 | 盘符本身 | 挂载点（目录） |
| 插入介质后 | 系统自动分配盘符 | udisks2 自动挂到 `/media`，或手工挂载 |
| 开机自动接入 | 系统自动 | fstab 中 `auto` 项在启动时挂载 |
| 目录映射到另一位置 | `subst` | `mount --bind` |

### 2.2 机制：三个层次的原因

1. **没有盘符机制。** Linux 只有一棵目录树，根是 `/`，所有存储必须并入同一棵树。存储设备在 `/dev/` 下只有**设备节点**（`/dev/sdc1` 等），设备节点用于直接读写块设备，**不提供按文件名访问文件的能力**；要按路径访问文件内容，只能经由挂载点。
2. **内核需要接入点才能派发 I/O。** VFS（虚拟文件系统）对上提供统一接口（open/read/write），对下分发到 ext4、xfs、ntfs-3g、tmpfs 等具体驱动。挂载完成的是"把文件系统与驱动绑定到目录"，此后该路径下的解析才走到那台设备。
3. **挂载点是权限边界。** 同一文件系统可挂到不同位置、以不同选项挂载（只读/可写、指定 uid），访问控制通过挂载选项表达，而不是盘符属性。

## 三、怎么挂

### 3.1 挂载命令的语法骨架

所有挂载，不论哪一类，最终都落到这个骨架：

```bash
mount [选项] <设备> <挂载点>        # 经典形式：显式指定挂什么、挂到哪
mount <挂载点>                      # 简写：设备与选项从 fstab 该挂载点的条目取
mount -a                            # 批量：挂 fstab 中所有 auto 项
mount -o remount,<新选项> <挂载点>   # 改选项：不卸载，就地改
mount --bind <源目录> <目标目录>      # 绑定：把目录接到另一个位置
mount --move <旧挂载点> <新挂载点>    # 搬家：不卸载，整体移到新位置
```

### 3.2 挂载后会遇到的两件事

挂载完成后，有两件事几乎立刻会被遇到，先说清楚，后面的"为什么重启就没了""为什么文件不见了"都由此而来。

**（1）挂载点原有内容被遮蔽。** 挂载点目录里原本的文件没有消失，只是被新挂上来的文件系统盖住；`umount` 之后重新可见。这就是"挂载之后目录里的东西不见了"的全部原因。因此**挂载点应为空目录**，非空目录不算错，但会让人误判。

**（2）命令行挂载是临时的。** 手敲 `mount` 完成的挂载只在本次运行期间有效，重启后消失。这是设计如此，不是故障。需要重启后依然生效，必须写入 `/etc/fstab`——下一节展开。

### 3.3 查看：挂之前看有什么，挂之后看挂上没有

挂载前要先知道机器上有哪些设备、打算挂哪个；挂载后要确认是否真的挂上、挂的是不是那一块。两组动作使用同一批工具，只在于看哪些字段。

```bash
# 挂之前：这台机器上有哪些块设备、各自类型与 UUID
lsblk                    # 设备树：谁是谁、挂没挂、挂在哪
lsblk -f                 # 附带文件系统类型、UUID、挂载点   ← 取 UUID 的首选
findmnt                  # 已挂载的树；空载时也能看现有挂载点

# 挂之后：确认真的挂上了
findmnt /mnt/data        # 查单个挂载点，有输出即挂上
df -hT /mnt/data         # 看容量与类型，顺带确认可用空间

# 按需单取
sudo blkid /dev/sdc1     # 指定分区的 UUID、类型、卷标
```

`findmnt` 有输出＝已挂载；`df -hT` 显示的容量与预期一致＝挂对了设备；`lsblk -f` 中该分区的 `MOUNTPOINTS` 列显示目标目录＝一致。三者任一不符，回到报错排查（见第八节）。

## 四、重启就没了：写入 fstab

### 4.1 fstab 的作用

`/etc/fstab`（file systems table）是开机挂载清单，系统启动时按其中条目逐行执行。写进去的条目每次开机生效，不需要手工操作。

写之前先明白一件事：**fstab 写错会让系统卡在启动阶段**。所以下面不是"先写、写坏了再救"，而是**先加防错参数，再写入，写完校验**。三道关：

| 关卡 | 手段 | 作用 |
| --- | --- | --- |
| 写前 | 带时间戳备份 `cp -a /etc/fstab /etc/fstab.$(date +%F-%H%M%S).bak` | 任何错误都能一键回滚 |
| 写入 | 选项里必带 `nofail` | 该设备不存在或挂不上时**不阻断启动**，系统照常进桌面 |
| 写后 | `findmnt --verify` + `mount -a` | 静态校验语法，再实测一次全量挂载 |

`nofail` 是这三道关里最关键的一项，因为它是**唯一在故障发生时仍然让你能进系统的参数**。备份要人动手去用，验证只能发现可知的错误；只有 `nofail` 是自动生效的兜底。凡是**可能不存在的设备**——外接盘、移动硬盘、双系统共享盘、网络盘——一律加。

### 4.2 fstab 六字段与可直接套用的写法

字段含义（`man fstab` 亦有说明）：

| 序 | 字段 | 规则 |
| --- | --- | --- |
| ① | 设备 | 见 4.3，结论是**写 **`UUID=` |
| ② | 挂载点 | 已存在的绝对路径；建议空目录 |
| ③ | 类型 | `ext4` / `ntfs-3g` / `vfat` / `iso9660` / `tmpfs` / `nfs`。NTFS 写 `ntfs-3g`，不写 `ntfs` |
| ④ | 选项 | 逗号分隔，**不能有空格**；与 `mount -o` 同一套语法 |
| ⑤ | dump | 现代系统一律 `0`（字段已废弃，仅为兼容保留） |
| ⑥ | pass | 根分区 `1`，本地盘 `2`，网络盘/U 盘/`noauto` 项 `0` |

**一套完整的操作写法**（把 `DEV` 和 `POINT` 改成实际值，其余不必动）。这段脚本处理了四件事：备份、取 UUID 并校验、判断条目是否已存在（存在就跳过，不重复写）、写完立即验证。

```bash
# 只改这两行
DEV=/dev/sdc1                 # 要挂的分区；用 lsblk -f 确认是哪一个
POINT=/mnt/data               # 挂载点；不存在会自动创建
TYPE=ntfs-3g                  # 按分区实际类型填
OPTS=noauto,users,nofail,utf8 # 选项；按 4.4 的表格挑选

# ---- 以下不必改 ----
sudo cp -a /etc/fstab "/etc/fstab.$(date +%F-%H%M%S).bak"   # 带秒备份，同日多次改不互相覆盖

sudo mkdir -p "$POINT"                                      # 建挂载点（已存在则无动作）
UUID=$(lsblk -no UUID "$DEV" | tr -d ' ')                    # 取该分区自己的 UUID
[ -n "$UUID" ] || { echo "UUID 未取到：设备名写错或分区无文件系统"; exit 1; }

if awk -v p="$POINT" '$1!~/^#/ && $2==p{f=1} END{exit !f}' /etc/fstab; then
  echo "fstab 已有 $POINT 的条目，跳过写入（改选项请手动编辑该行）"
else
  printf 'UUID=%s  %s  %s  %s  0  0\n' \
    "$UUID" "$POINT" "$TYPE" "$OPTS" | sudo tee -a /etc/fstab
  echo "已写入：UUID=$UUID  $POINT  $TYPE  $OPTS"
fi

sudo findmnt --verify || echo "校验未通过，先修 fstab，不要重启"
mount "$POINT" && findmnt "$POINT" && umount "$POINT"        # 实测一次：挂→看→卸
```

要点：

- **查重靠第二字段（挂载点）判断**，同一挂载点写两行会造成重复挂载或挂载失败；
- `users` 让普通用户可以挂载与卸载，否则每次都要 `sudo`；
- `noauto` 让开机不挂，配合 `users` 就是"户口在册、开机不报到"；
- 实测那行不加 `sudo`：能跑通，说明 `users` 生效了。

### 4.3 为什么设备一律写 UUID，以及该取哪一个

`UUID=`** 是什么**：格式化文件系统时写入卷头的一串标识，长度形如 `4AB004F1B004E4F3`（NTFS、FAT）或 `e0bbf986-1f2a-4c3d-…`（ext4）。它与"哪个接口、第几次探测"无关，只跟这个文件系统本身绑定，所以**重装系统、换接口、加减硬盘都不会变**（重新格式化才会变）。

**它解决的具体问题**：`/dev/sda`、`/dev/sdc` 这类名字是内核按**探测顺序**临时分配的。举例：机器上原有 `sda`（系统盘）+ `sdc`（机械盘），fstab 写了 `/dev/sdc1` 挂数据盘；某天插了一块移动硬盘并调整了 SATA 接线，开机后机械盘变成 `sdb`、移动硬盘变成 `sdc`——系统按 fstab 去 `/dev/sdc1` 找数据盘，实际挂上来的是移动硬盘。这种事故不会报错，只会静默挂错。写 UUID 之后，设备名怎么漂都不影响。

**因此写 UUID，不写 **`/dev/sdXn`（`/dev/disk/by-label/卷标` 也可用，但卷标可重复、可随意改，不如 UUID 可靠）。

**该取哪一个**：机器上有几个分区就有几个 UUID，取的是**要挂的那个分区的 UUID**，认它的两条途径：

```bash
lsblk -f                          # 一行一个分区，看清 MOUNTPOINTS 空着的那一行对应的 UUID
sudo blkid /dev/sdc1              # 已知设备名时直接取，输出里 UUID="..." 引号内即所需
```

取完必须核对两点：**这一行的 SIZE 与卷标是不是你要的那块盘**；**这一行的 FSTYPE 与后面要写的类型是否一致**。UUID 抄错一位的后果与写错设备名相同——静默挂错或挂不上。

### 4.4 选项表

`mount -o` 与 fstab 第 4 字段是同一套选项，写法与含义一致，区别只在生效范围：前者只影响本次挂载，后者每次由 fstab 挂载时都生效。

| 选项 | 作用 | 为什么/什么时候用 |
| --- | --- | --- |
| `defaults` | 等价 `rw,suid,dev,exec,auto,nouser,async` | 不特别指定时的基准值；单独写无特殊效果 |
| `auto` / `noauto` | 开机是否自动挂载 | 常用盘用 `auto`；偶尔才用的大盘用 `noauto`，省开机时间与失败风险 |
| `nofail` | 挂载失败不阻断启动 | 外接盘、共享盘、网络盘**必加**；不加则设备不在时可能开不了机 |
| `users` / `user` | `users` 任何用户可挂可卸；`user` 仅挂载者本人可卸 | 希望免 sudo 时用 |
| `ro` / `rw` | 只读 / 可读写 | 查看光盘镜像、检查故障盘、Windows 未干净关闭的 NTFS 卷，一律 `ro` |
| `uid= gid=` | 指定挂上后文件的属主、属组 | NTFS/FAT 本身不存 Unix 权限，不指定则文件全归 root，普通用户无法写入 |
| `umask=` / `dmask=` / `fmask=` | 目录与文件的权限掩码 | 与 `uid/gid` 配合控制权限；`ntfs-3g` 默认 022/133（目录 755、文件 644），不确定就不写 |
| `noatime` | 不更新访问时间 | 大数据盘、频繁读写的盘可减少写入；一般用途不必加 |
| `utf8` | 以 UTF-8 解析文件名 | NTFS/FAT 上有中文文件名时必须，否则乱码 |
| `nosuid,nodev,noexec` | 禁止 setuid、设备文件、可执行文件 | 挂 U 盘等不可信介质时使用，防止其中的程序取得特权 |
| `x-systemd.automount` | 首次访问该路径时才挂载，闲置可自动卸 | 进阶用法；适合开机慢又不希望漏挂的盘 |

### 4.5 写完必须验证

```bash
sudo findmnt --verify --fstab     # ① 静态校验语法与可解析性，报错会指出具体行
sudo mount -a                     # ② 实际执行一次全量挂载（noauto 项跳过）
sudo findmnt --verify             # ③ 再确认整份表通过
sudo systemctl daemon-reload      # ④ 仅使用 x-systemd.* 选项时需要
```

四步都不报错，才算可用。`mount -a` 是把将来开机要做的事**先做一遍**，错误此刻暴露，而不是留到下次重启。

### 4.6 万一起不来：回滚

前提：照 4.1 做了备份。若系统停在启动阶段并提示 fstab 相关错误：

1. 按提示进入维护 shell，或用 Live 介质启动；
2. 找回备份（文件名带时间戳），覆盖回原文件：
   ```bash
   ls /etc/fstab.*.bak                 # 确认有几个备份，选改前那个
   cp /etc/fstab.2026-10-27-213000.bak /etc/fstab
   ```
3. `reboot` 验证。

如果改前没备份，就手工删掉或注释（行首加 `#`）可疑的那一行——新增条目往往就是出错的那一行。

## 五、挂载的两大类：自动与手动

分法只有一条主线：**挂载动作由谁发起**。自动挂载不需要人敲 `mount`，手动挂载需要。

### 5.1 自动挂载

| 触发时机 | 实现机制 | 挂到哪 |
| --- | --- | --- |
| 开机时 | `/etc/fstab` 中 `auto` 项（`defaults` 已含） | fstab 第 2 字段指定的目录 |
| 插入介质时 | udisks2（桌面自动挂载服务） | 通常 `/media/<用户名>/<卷标>` |
| 首次访问某路径时 | fstab 中 `x-systemd.automount` | 指定目录，闲置可自动卸 |

### 5.2 手动挂载

同样是手动敲命令，按**持续多久**再分三种：

| 类型 | 写法 | 生命周期 | 适用 |
| --- | --- | --- | --- |
| 临时挂载 | 命令行 `mount`，不写 fstab | 重启即失效 | 试错、一次性查看 |
| 永久挂载 | `mount` 成功后再写入 fstab | 每次开机自动生效 | 常用盘、共享盘 |
| 永久但按需 | fstab 中 `noauto,users` | 有记录、开机不挂；用时手动挂 | 偶尔才用的大盘 |

第三类是前两类的一半：**fstab 里有户口，但不开机报到**。日常一条 `mount /挂载点` 即可，`users` 让普通用户免 sudo。写法见 4.2 脚本，实例见 7.1。

### 5.3 挂的对象：能挂的不只是硬盘分区

| 对象 | 典型命令 | 用途 |
| --- | --- | --- |
| 块设备分区 | `mount /dev/sdc1 /mnt/data` | 硬盘分区、U 盘、移动硬盘 |
| 按 UUID / LABEL | `mount UUID=xxxx /mnt/data` | 推荐做法，避免 `/dev/sdXn` 顺序漂移 |
| 目录（绑定挂载） | `mount --bind /src /dst` | 同一份数据出现在两个路径，等价 Windows `subst` |
| 镜像文件（ISO） | `mount -o loop,ro x.iso /mnt/iso` | 相当于 Windows 的虚拟光驱，见 7.4 |
| 内存文件系统 | `mount -t tmpfs -o size=2G tmpfs /mnt/ram` | 数据在内存中，重启即失，见 7.3 |
| 网络文件系统 | `mount -t nfs 主机:/导出 /mnt/nfs` | 依赖网络与服务端可用 |
| 伪文件系统 | `-t proc`、`-t sysfs` | 系统启动时挂载，日常不手动操作 |

## 六、卸载：怎么保证数据不丢

### 6.1 命令

```bash
umount /mnt/data          # 参数是挂载点，不是设备
umount -R /mnt/data       # 连同其下子挂载一起卸
umount -l /mnt/data       # 惰性卸载：立即摘出命名空间，占用进程结束后真正释放（最后手段）
sync                      # 落盘；拔盘、关机前必须执行
```

`mount` / `umount` 属于 util-linux 包，版本用 `mount --version` 查（示例环境 util-linux 2.39.3，libmount 2.39.3）。

### 6.2 为什么卸载会失败

理解"设备层/数据层"两句话即可：

- **设备层**：`umount` 做的事是把文件系统从目录树上摘下。只要还有进程持有该文件系统上的**文件句柄**（不分前后台），或某进程的**当前工作目录**落在该挂载点内，摘下就会让这些引用悬空，内核因此拒绝——这就是 `target is busy` 的来源。
- **数据层**：写入并非立即落盘，而是先进页缓存。`umount` 在摘除前会先把缓存刷回设备，这是它比"直接拔"安全的根本原因。

排查顺序：退出该目录 → 关掉占用它的程序 → `fuser -mv` / `lsof +D` 找出剩余进程 → 最后才用 `umount -l`。

### 6.3 数据安全的四条规则

- **拔盘或关机前先 **`umount`**，再 **`sync`**。** Linux 页缓存策略较 Windows 更积极，跳过卸载直接断电，丢失的是缓存中尚未写回的副本。
- **返回 **`target is busy`** 时不要直接拔。** 卸载未完成，数据仍在缓存。
- `umount -l`** 不是"立刻安全"。** 它只是把挂载点从命名空间摘除，实际释放要等占用进程结束；此时断电仍有风险。
- **写坏的 fstab 与写坏的盘是两件事。** 前者靠备份回滚（4.6），后者需 `fsck` 或回 Windows `chkdsk`。

Windows 的"安全删除硬件"与 Linux 的 `umount` 是同一机制：检查句柄、刷写缓存、断开接入。

## 七、应用举例

### 7.1 大容量机械盘：开机不挂、用时免 sudo

场景：一块 20T 机械盘，日常不需要，偶尔要翻资料。开机挂上等于每次空转，还多一个开机失败的风险点。

按 4.2 的脚本执行，参数取这组：

```bash
DEV=/dev/sdc1
POINT=/mnt/data
TYPE=ntfs-3g
OPTS=noauto,users,nofail,utf8
```

脚本完成后，日常只需两条：

```bash
mount /mnt/data      # 用前，不需要 sudo
umount /mnt/data     # 用后，无输出即成功
```

挂载点位置也可以选 `~/mnt/data`：建目录免 sudo、文件管理器里更顺手，数据同样落在外接盘。写作 `POINT="$HOME/mnt/data"` 即可，注意 `uid/gid` 需按实际用户填写。

### 7.2 双系统共享盘：让 Linux 稳定读写 NTFS 分区

场景：与 Windows 共用一个 NTFS 分区，要求开机自动可用、文件归属当前用户、读写正常。

```
UUID=4AB004F1B004E4F3  /mnt/winc  ntfs-3g  defaults,nofail,uid=1000,gid=1000,dmask=022,fmask=133,utf8  0  0
```

要点：

- `ntfs-3g` 而非 `ntfs`：后者是已弃用的类型名，现代内核要么不识别，要么只能只读挂载；
- `uid` / `gid`：NTFS 不存 Unix 权限，不指定则挂上后文件全归 root，普通用户无法写入；
- `dmask` / `fmask`：设定目录与文件的权限掩码，`022/133` 对应目录 755、文件 644。这也是 `ntfs-3g` 的默认值，此处显式写出只是让配置自解释，省略效果相同；
- `nofail`：**这一项必须有**。共享盘在另一套系统下用，本机开机时可能不存在，没有 `nofail` 会卡在启动阶段；
- `utf8`：中文文件名必须用它解析，否则显示为乱码；
- Windows 侧必须**彻底关机**（关闭快速启动与休眠）：否则卷处于"未干净关闭"状态，Linux 侧检测到后只能只读挂载，写入会失败。

### 7.3 内存盘：给临时文件一个高速落点

场景：内容用完即弃、但读写频繁的中间数据——编译中间文件、大型压缩包解压、浏览器缓存、视频剪辑的临时渲染文件。原则是**丢了不心疼，但放硬盘上又太慢或太伤 SSD**。

```bash
mkdir -p ~/ram                                            # 挂载点
sudo mount -t tmpfs -o size=2G,mode=700,uid=1000,gid=1000 tmpfs ~/ram
df -hT ~/ram                                              # 确认类型 tmpfs、容量 2.0G
sudo umount ~/ram                                         # 卸载，内容随之消失
```

写进 fstab（开机即有，写法同 4.2）：

```
tmpfs  /home/<用户名>/ram  tmpfs  size=4G,mode=1777,nosuid,nodev  0  0
```

**典型用法一：把编译、打包的中间目录指到内存盘。** 这类目录写入量极大、寿命只有几分钟，放 SSD 上是白耗写入寿命。

```bash
mkdir -p ~/ram/build
cd 源码目录
TMPDIR=~/ram/build make        # 编译期临时文件落到内存盘
df -hT ~/ram                   # 观察已用容量，接近上限就调大 size
```

**典型用法二：解压大型压缩包再装、再删。** 解压产生的几万个碎文件写在机械盘上很慢，写进内存盘可快数倍；安装完直接卸载，连删除都省了。

```bash
cd ~/ram && tar xf /path/to/包.tar.gz && cd 解压目录 && <安装命令>
cd ~ && sudo umount ~/ram      # 不需要清理，卸载即全部释放
```

**典型用法三：受内存限制的场景——数据库、容器、虚拟机内存盘。** 例如测试数据库的 `tmpdir`、容器的临时卷，重启即恢复干净状态，也不必担心残留数据。

要点：

- **重启即清空**，只放可丢的数据；需要留存的内容一律不放；
- **占用的是真实物理内存**，不是"免费的缓存"。32G 内存划 2\~4G 合适；拿不准就用 `free -h` 看可用量，取 **available 的 1/8 以内**；
- **写满的后果与硬盘不同**：`tmpfs` 达上限会报 `No space left on device`；`ramfs` 无上限，写满会触发 OOM 杀掉进程，**因此只用 **`tmpfs`**，不用 **`ramfs`；
- `tmpfs` 内容可被换出到 swap（若启用），所以"内存盘上的数据一定在内存里"并不绝对；
- 重启前未卸载不影响数据安全（数据本就可丢），但若有进程仍在写，关机过程中会直接被中断；
- 与 Windows 的 UltraRAMDisk 功能相近，但后者能把内存盘内容保存为镜像文件、开机再加载，`tmpfs` 没有这个能力；需要跨重启保留的，用 `rsync` 或脚本在关机前复制到硬盘。

### 7.4 ISO 镜像：相当于虚拟光驱

场景：查看光盘镜像内容、安装软件源、取用里面的文件，但不必刻盘或解压。

```bash
sudo mkdir -p /mnt/iso
sudo mount -o loop,ro 镜像.iso /mnt/iso   # loop=把文件当块设备；ro=只读
ls /mnt/iso                               # 浏览内容
sudo umount /mnt/iso                      # 用完必须卸
```

要点：

- `loop` 让内核把这个文件当作块设备使用，效果等同插入一张光盘；
- `ro` 避免误改镜像内容；
- 用完必须卸载，否则镜像文件被占用，无法删除、移动或改名；
- 需要开机自动可用时，fstab 里写 `镜像路径 /mnt/iso iso9660 loop,ro,nofail 0 0`（路径与类型按实际填写）。

## 八、问题解决

### 8.1 报错速查

| 报错 / 现象 | 根因 | 处理 |
| --- | --- | --- |
| `target is busy` | 有进程持有该挂载点内的文件句柄或工作目录 | `cd ~` 退出 → `fuser -mv <挂载点>` 或 `lsof +D <挂载点>` 定位 → 结束进程后重试 → 最后才用 `umount -l` |
| `must be superuser` | 权限不足 | 加 `sudo`，或 fstab 写 `users` |
| `wrong fs type, bad option` | 类型名错误，或 `ntfs-3g` 未安装 | `sudo apt install ntfs-3g`；类型写 `ntfs-3g` |
| `unknown filesystem type 'ntfs'` | 使用已弃用的类型名 | 改 `ntfs-3g`，或 `-t ntfs3`（内核驱动） |
| 挂载后目录内容"消失" | 遮蔽效应，挂载点非空 | `umount` 即恢复；后续改用空目录 |
| 重启后挂载失效 | 使用了临时 `mount` | 写入 fstab（见第四节） |
| 插入了盘但挂上来的是另一块 | fstab 里写了 `/dev/sdXn`，设备名漂移 | 改 `UUID=`（见 4.3） |
| 插入 U 盘无反应 | 桌面自动挂载服务未运行或介质异常 | 手工 `mount /dev/sdX /mnt/xxx` 观察报错 |
| 开机卡在 fstab 报错 | fstab 条目错误且无 `nofail` | 进维护 shell 用备份回滚（见 4.6）；今后一律加 `nofail` |
| Windows 休眠/快速启动后的分区无法读写 | NTFS 卷处于未干净关闭状态 | 回 Windows 彻底关机或关闭快速启动；Linux 侧只能只读挂载（`-o ro`） |
| 图形界面弹出/卸载无反应 | 前端在依赖或占用检查上静默失败 | 改用命令行 `umount`，并用 `fuser`/`lsof` 查占用 |

### 8.2 设备与数据损坏

- 分区表或文件系统损坏 → `fsck`（ext4）、回 Windows 用 `chkdsk` 修 NTFS；GParted 不修 NTFS
- 数据误删 → **立即停止向该设备写入**，再作恢复（TestDisk / PhotoRec；Windows 侧 DiskGenius）
- 工具对照：看分区 DiskGenius ↔ `lsblk`；建分区、格、调大小 DiskGenius ↔ GParted（购物车模式，排队后点绿勾才执行）
- 双系统的现实价值：**哪块盘故障，就挂到工具齐全的那一侧处理**

## 九、值得坚持的几条

1. **fstab 里一律写 **`UUID=`**，不写 **`/dev/sdXn`**。** 设备名随探测顺序、接口、加减盘变化，重启后可能静默指向别的盘。
2. **可能不存在的设备一律加 **`nofail`**。** 少一个参数，可能换来一次开不了机。
3. **改 fstab 前先备份，改完先 **`findmnt --verify`**，再 **`mount -a`** 实测。**
4. **同一挂载点只写一行。** 写入前先查重，脚本见 4.2。
5. **机械盘用 **`noauto,users`**，不用 **`auto`**。** 省得每次开机空转；`users` 让挂载免 sudo。
6. **挂载点用空目录。** 非空目录挂载后被遮蔽，是"文件不见了"这类事故的唯一来源。
7. **NTFS 盘在 Windows 侧彻底关机后再切系统。**
8. **拔盘顺序固定为 **`umount`** → **`sync`** → 断电。** 顺序颠倒等于跳过卸载。
9. **图形界面的弹出功能不可依赖。** 它在依赖缺失或占用检查上会静默失败，命令行 `umount` 的报错才可读。
10. **数据误删后立即停手。** 任何写入（包括系统日志）都可能覆盖待恢复扇区。
