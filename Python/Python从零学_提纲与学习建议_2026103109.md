# Python 从零学：提纲与学习建议

> 目标定死两件事：**看得懂别人写的代码**、**能验证结果对不对**。
> 不是"能独立开发软件"。这个目标决定了学什么、以及更重要的是——**不学什么**。

---

## 一、先明确：目标决定路线

同样叫"学 Python"，三种目标的路线完全不同：

| 目标 | 重点 | 典型误区 |
|---|---|---|
| 做开发、写产品 | 工程结构、框架、数据库、部署 | 学三年还在配环境 |
| 数据分析 | pandas、统计、可视化 | 语法没打牢就上 pandas，报错看不懂 |
| **读懂 + 验证（本次目标）** | **数据结构识别、控制流、输入输出与副作用、调试与比对** | 死记 API、追求写"优雅"代码 |

对应的取舍很清楚：

- **读得懂**靠的是"认形状"，不是"背函数"。看见 `{}` 知道是字典，看见 `df.groupby()` 知道在按某列分组——这层认得，代码就读通了七成。
- **验得对**靠的是"看见中间值"和"做对比"。这两件事跟写代码能力关系不大，跟调试习惯关系极大。
- 所以：**语法学到能读为准，工具学到能看中间值为准**，其余一律延后。

---

## 二、路线图：五个阶段

节奏建议：每天 30–60 分钟，**4–6 周**走完阶段 0 到阶段 4。阶段 5 是练手，不设期限。

```
阶段0 环境（半天）      →  能跑起来、能装包、能改一行
阶段1 语言骨架（1–2 周） →  读懂 30 行以内的小脚本
阶段2 读码四步法（3 天） →  拿到陌生脚本会拆
阶段3 认库（1 周）       →  知道每段代码在跟谁打交道
阶段4 验证结果（1 周）   →  能判断结果对不对、能定位错在哪
阶段5 三个小项目（持续） →  把上面四条串起来
```

### 阶段 0：环境（半天）

**要会的四件事**

1. 确认解释器在不在：`python3 --version`。Linux 上命令是 `python3`，不是 `python`（Windows 上通常反过来）。这是两套系统的命名习惯差异，不是谁对谁错。
2. VS Code 装上 Microsoft 官方 Python 扩展，右下角选解释器。编辑器本身的操作不用重新学。
3. 交互式解释器（REPL）：终端敲 `python3` 回车，进入"敲一句、回一句"的模式，`exit()` 退出。这个东西最像 DOS 命令行，是试语法最快的工具——**不确定某句什么意思，扔进 REPL 里跑一下**，比查资料快。
4. 跑文件：`python3 文件名.py`。

**虚拟环境（venv）是什么**

一句大白话：**给这个项目单独开一个装包的抽屉**。系统的 Python 是公共抽屉，谁都能往里塞东西，容易打架；venv 是这个项目专用的，删掉目录就干净了。跟"绿色便携软件不污染系统"是同一个思路。

```bash
python3 -m venv .wbvenv          # 建抽屉（只在项目根建一次）
source .wbvenv/bin/activate      # 进抽屉，提示符前面会出现 (.wbvenv)
pip install 包名                  # 装包，只装进这个抽屉
deactivate                       # 出抽屉
```

**验收**：能写出一个 `hello.py` 打印中文不乱码；能在 venv 里装一个包并 `import` 成功。

### 阶段 1：语言骨架（按"读代码时眼睛扫什么"排序）

教材通常按语言规范讲，读代码不是这个顺序。按下面的顺序学，每一步都对应读代码时的一个动作：

| 顺序 | 内容 | 读代码时它在干什么 |
|---|---|---|
| 1 | 变量与 `=` | 给值贴个标签，后面用标签指代 |
| 2 | 五种值：整数/小数、字符串、True/False、None、容器 | 判断这一行在处理什么数据 |
| 3 | **四个容器**：`[]` 列表、`()` 元组、`{}` 字典、`set` | 读代码 90% 的卡点在这里 |
| 4 | 索引、切片、`in`、`.get()` | 从容器里取东西 |
| 5 | 缩进 = 代码块（冒号 + 缩进，没有大括号） | 判断哪几行属于同一个分支 |
| 6 | `if / elif / else`、`and / or / not` | 走哪条路 |
| 7 | `for ... in ...`、`range()`、`enumerate()`、`while` | 重复做了什么、重复几次 |
| 8 | `def` 函数：参数、`return`、默认参数 | 这段被谁调用、交回什么 |
| 9 | `open()` / `with`、`pathlib` | 读写文件在哪一步发生 |
| 10 | `import` 与模块 | 这个陌生的名字从哪来 |
| 11 | `try / except` | 出错时程序怎么走（读报错也要用） |

重点说明两条：

- **容器优先练**。列表和字典长什么样、`[0]` 和 `['key']` 的区别、`for x in dict` 拿到的是键不是值——这几个坑认清了，读代码的阻力会掉一大半。
- **缩进不是排版，是语法**。大括号语言里缩进只是好看，Python 里缩进错了程序就错。这是从大括号语言迁移过来最容易栽的一处，靠编辑器自动缩进基本能规避。

**验收**：给一段 30 行以内、只用上述内容的脚本，能说出"它算了个什么"。

### 阶段 2：读代码四步法（核心方法，比语法更值钱）

拿到任何陌生脚本，固定按四步拆，不要从头逐行读：

1. **找入口**——程序从哪开始跑。
   找 `if __name__ == "__main__":`（意思是"直接运行这个文件时才执行下面"）、找 `def main()`、找文件最后几行。
2. **找数据形状**——进来的东西是什么。
   是列表？是"字典的列表"？是读的一个文件？把最外层结构写下来：`list[dict]`、`dict`、`DataFrame`。
3. **找出口**——最后交出去什么。
   `print` 到屏幕、`return` 给调用者、写进文件、写进数据库。四种去向，判断标准不同。
4. **找副作用**——会不会动我的东西。
   删文件、改文件、发网络请求、装包、连数据库。**凡是有副作用的脚本，先只读不改地跑一遍逻辑，再决定要不要执行。**

**画三格图**：输入 → 处理 → 输出。中间那格再拆成几步。画得出来，就是读懂了；画不出来，说明卡在某一格，回去补那一段。

### 阶段 3：认库（只认脸，不背 API）

分清两批，按需查文档：

- **标准库（装完就有）**：`os` / `pathlib`（路径文件）、`sys`、`json`、`csv`、`re`（正则）、`datetime`、`random`、`shutil`（复制移动）。
- **第三方（要装）**：`requests`（取网络数据）、`pandas`（表格）、`openpyxl`（Excel 文件）。

**认库的三个动作**（比背 API 有用得多）：

1. 看 `import` 行 → 列出这段代码用了哪几个库，各自负责哪一段。
2. 猜类型 → 用 `type(变量)` 打印出来确认。
3. 查不明白的名字 → `dir(对象)` 列出它能干什么，或查官方文档。

**链式写法怎么读**：`df.groupby("城市")["销量"].sum()` 从**左往右**读成一句话——"拿这张表，按城市分组，取出销量列，求和"。链式不是新语法，就是一串操作接一串操作。

**验收**：陌生脚本里出现的库，能说出每个负责哪一段、数据在它们之间怎么传。

### 阶段 4：验证结果（大多数教程不讲，但这是你的主要目标）

分三层，从粗到细：

**第一层：让中间值露出来**

- `print()` 插在关键处，看值对不对。
- VS Code 调试器：行号左边点一下下断点 → F5 启动 → 程序停在那一行 → 左边"变量"面板能看到**所有**变量当前的值，F10 单步、F11 进入函数。这套操作跟其他语言的调试器是同一个逻辑，会一个就会一片。**这是验证结果最有效的手段，值得专门花半小时摸熟。**
- 小技巧：`print(f"{变量=}")` 会直接打印出"变量名=值"，比手写标签省事。

**第二层：给自己设关卡**

`assert 条件, "出错时说的话"`。条件不成立程序立刻停在那里。把"我认为这里应该是 3"写成断言，程序自己会告诉你对不对。

**第三层：做对比**

- **小样本手算**：取 5 行数据，自己在纸上算出结果，再让程序算，两边对不上就查。
- **控制变量**：只改一个输入，看输出是否按预期跟着变。不改输入输出却变了 → 有隐藏状态（缓存、随机、时间、文件残留）。
- **反向验证**：把结论倒推回输入，看能不能还原。比如"统计出总数 1000"，就抽查 3 条明细能不能凑上。

**读报错（Traceback）的固定姿势**：**从下往上读**。

- 最后一行：错误类型和人话说明（`KeyError: 'age'` = 字典里没这个键；`FileNotFoundError` = 路径不对；`IndentationError` = 缩进错；`ModuleNotFoundError` = 没装包或没进 venv；`SyntaxError` = 语法或全角标点）。
- 倒数第二行：出错的文件和行号。
- 再往上：调用链，能看出是从哪里一路调过来的。

**验收**：给一个"结果是错的"的脚本，能定位到具体哪一行、哪个变量的值不对。

### 阶段 5：三个小项目（练"读 + 验"，不是练开发）

每个都控制在 50 行以内，重点在流程而不在功能：

1. **读一个 CSV，统计某一列**（pandas）。练：数据形状、链式写法、小样本比对。
2. **批量重命名文件**（`pathlib`）。练：副作用控制。**要求先写"只打印不动手"的版本（dry-run），确认打印出来的名单对了，再放开真正改名**——这个习惯比代码本身重要。
3. **调一个网络接口，取回 JSON 打印其中几个字段**（`requests` + `json`）。练：外部数据不可控时怎么验证（字段可能缺、可能类型不对）。

每个项目的固定流程：**先猜结果 → 再跑 → 解释差异**。差在哪，就是那天真正学到的东西。

## 三、读代码检查表（打印出来放旁边）

拿到陌生脚本，逐条打勾：

- [ ] 入口在哪一行？谁调用谁？
- [ ] 输入是什么？最外层是 list 还是 dict 还是 DataFrame？
- [ ] 输出到哪？print / return / 写文件 / 写库？
- [ ] 有没有副作用？（删、改、发请求、连库）
- [ ] 用了哪些库？每个库负责哪一段？
- [ ] 有没有 `try/except` 在吞错误？（吞了错误 = 出问题时你看不到原因）
- [ ] 有没有硬编码路径、账号、密钥？（有就说明不能直接跑）
- [ ] 循环的边界是多少？空输入会怎样？
- [ ] 能不能画出"输入 → 处理 → 输出"三格？
- [ ] 我要验证结论，第一件事该 print 哪个变量？

## 四、学习建议（方法比内容重要）

1. **边读边跑，改一行看变化。** 任何示例代码，改一个数字、改一个变量，重跑，看结果怎么变。这是理解最快的一条路，比读三遍解释有效。
2. **只学够用。** 遇不到的概念不学。判断标准很硬：**"这段代码里出现了，我才学"**。
3. **报错是教材，不是失败。** 故意写错——少个冒号、用中文引号、键名打错——看报错长什么样。见过一次，下次一眼认出。
4. **不抄教程项目。** 记账本、博客系统、爬虫框架这类，时间会全耗在环境和配置上，跟"读懂 + 验证"的目标无关。
5. **建一个代码笔记**，三栏就够：`这段代码干什么` / `哪一句我没看懂` / `查了什么、结论是什么`。第三栏是唯一会反复回看的内容。
6. **阅读顺序：自己写的 → 别人写的 50 行 → 别人写的 200 行。** 不要一上来读框架源码，那不是学习材料。
7. **卡住超过 30 分钟就记下来跳过**，隔天回头看，多数会自己通。硬啃会消耗掉全部耐心。
8. **每天留一个能跑、能看到输出的东西。** 只看不练，一周就归零。

## 五、明确不学的（黑名单）

这一栏和提纲一样重要。以下内容在"读懂 + 验证"的目标下**第一阶段全部跳过**，遇到再查：

- 面向对象三大特性、继承、多态 —— **但要能认出 `class` 是什么**（读代码一定会遇到类）。**认得 ≠ 会写**，这个区分要守住。
- 装饰器 `@`、生成器 `yield`、异步 `async/await`、多线程 —— 见到知道"这是个进阶写法"，跳过即可。
- 算法与数据结构课程、刷题。
- Web 框架（Django / Flask / FastAPI）、前端、数据库设计、打包发布。
- 类型注解、单元测试框架（`assert` 够用）。
- 追求"优雅"的写法（列表推导式可以先认得、不必强求会写）。

## 六、常见坑（按踩中概率排）

1. **全角标点**。中文输入法下的 `（ ）`、`，`、`" "` 会让程序报 `SyntaxError`，肉眼几乎看不出来。新手第一大坑。
2. **`python` 与 `python3`**。Linux 上一般要写 `python3`；Windows 上装完通常 `python` 就能用。两边不一致时先 `which python3` 查清楚在调哪个。
3. **`pip` 报 `externally-managed-environment`**。系统的 Python 不允许直接装包，正经做法就是进 venv（阶段 0 那个"抽屉"），不要去 `--break-system-packages` 硬装。
4. **编码**。读写文本文件时显式写 `encoding="utf-8"`；Windows 默认编码不是 utf-8，跨系统传文件容易乱码。
5. **路径分隔符与当前工作目录**。Linux 用 `/`，Windows 历史上用 `\`（Python 里 `\` 要写成 `\\`）。"脚本在 A 目录能跑、在 B 目录报找不到文件"，根因几乎都是**相对路径是相对"当前所在目录"算的**，不是相对脚本所在目录。用绝对路径或 `pathlib` 能绕开这类问题。
6. **缩进混用 Tab 和空格**。看起来一样，程序会报错。让编辑器统一转空格。
7. **`import` 了自己写的文件却报找不到**。当前目录、`sys.path`、包结构的问题；先确认运行位置对不对。

## 七、怎么算学成了

一条终验，能过就是达到了目标：

> 拿到一份 100 行左右、**没见过的** Python 脚本，不开编辑器也能回答四个问题：
> 1. 它读什么？
> 2. 它算什么？
> 3. 结果输出到哪？
> 4. 运行它会不会改我的文件？
>
> 再进一步：给我一个"结果明显不对"的脚本，我能指到具体哪一行、哪个变量。

四个问题答不全，回头补哪一阶段很明确：1、2 卡住 → 阶段 1 容器和控制流；3、4 卡住 → 阶段 2 四步法。

## 八、三个趁手的工具

| 工具 | 用途 | 什么时候用 |
|---|---|---|
| 交互式解释器（REPL） | 敲一句回一句，试语法 | 不确定某句什么意思 |
| VS Code 调试器（断点 + 变量面板 + 单步） | 看程序跑到某行时所有变量的值 | 验证结果、定位错在哪一行 |
| Python Tutor（网页版，可视化单步执行） | 把每一行执行后变量和内存画出来 | 读不懂循环和容器嵌套时，看一遍就通 |
