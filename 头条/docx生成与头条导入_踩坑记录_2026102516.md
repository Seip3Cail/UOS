# docx 生成与头条导入 · 踩坑记录

2026-10-25 整理。背景：把《显卡一日一价》文章做成图文混排 docx，导入头条号文章编辑器。

## 一、docx 生成（脚本：/home/wsqw/wsqw_UOS/生成发布docx.sh）

| 坑 | 现象 | 结论 |
|---|---|---|
| pip3 命令不存在 | deepin 没装独立 pip 命令 | 用 `python3 -m pip`，或干脆不装包 |
| apt 源没有 python3-docx | `E: 无法定位软件包` | 别指望 apt |
| python3-venv 装不上 | 系统依赖版本不匹配 | 别指望 apt |
| venv 版本错配 | 3.12 壳配 3.13 的 pip，lxml 等二进制包必坏 | venv 必须与基础 python 同版本，目录名带版本号 |
| 装包超时 | 国外官方源、部分镜像直连超时 | 清华源为主，阿里云兜底 |
| docx 有字没图 | 图片 XML 的 wp: 命名空间没声明，整块被丢 | 命名空间必须齐全（已修） |

**最终方案**：docx 用纯 Python 标准库（zipfile）手工拼 OOXML，**零依赖**，任何 python3 都能跑；
包管理走常备虚拟环境 `~/.wbvenv-3.13`（建环境.sh，幂等），两套互不拖累。
图片尺寸在脚本里改一个数字：`INCH = 4.5`（英寸）。

## 二、头条导入（实测 2026-10-25）

- **文章 vs 微头条，排版能力是两个等级（实测确认）**：
  - **文章编辑器**：真编辑器，光标可落到任意段落，图片**直接插入光标处**，图文混排没问题；
  - **微头条**：只是"文字框 + 图片附件"，光标进不了文字区插图，图片永远排在文末，没有混排。
  - 结论：**要图文混排只能发文章**；微头条按"纯文本 + 文末配图"设计内容。
- "文档导入"会把文字和图片拆成两步（文字进正文，图片单独成区），不自动嵌图。
- 对策（按优先级）：
  1. **粘贴法**：用 WPS/LibreOffice 打开 docx → 全选复制 → 粘贴进**文章编辑器**，富文本粘贴通常能把内嵌图带上（待实测确认）。
  2. **两步法**：文档导入文字后，光标点到目标段落 → 从图片区把图插入光标处（文章编辑器支持，图按 图1装机怀旧→图2华强北柜台→图3显存特写 对号入座）。
- docx 里图片已居中、4.5 英寸宽，导入后在文章编辑器里还可拖角微调。

## 四、首日发布实测（2026-10-25 晚）

- 两篇（微头条 + 文章）**均过审发布**，账号流水线走通。
- **但图文没有真正混排**：发布时的文章是把 docx"文档导入"后直接发的，没做光标插图那一步，图片都堆在后面。
- **结论修正**：头条文章编辑器"能"在光标处插图 ≠ 文档导入会自动混排——**混排必须手工做**，导入或粘贴只负责文字。
- 明天的决策规则：
  1. 先试**粘贴法**一次：WPS 开 docx → 全选复制 → 粘贴进文章编辑器，看图是否原位带上；
  2. 粘贴法不行 → **放弃 docx 环节**，文章按"发布稿 md 纯文本 + 图N 文件"交付：贴文字 → 光标点段落 → 插图，3 张图一分钟；
  3. docx 只在粘贴法有效时保留，否则它就是多余环节。
