---

## 一、这是什么

一个离线的小工具，由三块拼成：

| 页面 | 干什么 |
|---|---|
| `index.html` 答疑 | 打一句话问 SQL 的事，答案从教程里挑出来，每句带出处 |
| `reader.html` 阅读版 | 五份教程合成一本，左目录右正文，86 万字 |
| `practice.html` 练习场 | 真跑 SQL（浏览器内置 SQLite），出题、你写、机器判对错 |
| `quiz.html` 自测 | 24 道选择题，选完立刻判，答错当场讲清楚 |

四个页面靠顶栏互相跳，阅读版的每一节都有锚点，答题答错能一键跳回原文。

---

## 二、三块怎么配合

- **答疑**：临时想不起来某个语法、某个概念的区别，问一句。答不上来它会直说"没讲"，不编。
- **练习场**：知道怎么写但手生，或者想验证"我这么写对不对"。判定只看**结果对不对**，不看跟你写得像不像——同一道题有多种写法，都对。
- **自测**：检查概念有没有记混。比如"COUNT(*) 和 COUNT(comm) 差在哪""AVG 遇 NULL 怎么算"，这类地方最容易记反。

## 四、练习场的库

自己搭的一套小库，两套 schema 共 7 张表：

**教学库（经典 scott 结构）**
- `dept` 部门 4 行
- `emp` 员工 14 行（含无佣金、无上司、跨四个部门的各种情况）
- `salgrade` 工资等级 5 行

**业务库（电商）**
- `customer` 客户 8 行（其中 1 人从未下单）
- `product` 商品 10 行，5 个分类
- `orders` 订单 20 单（3 单已取消）
- `order_item` 订单明细 35 行

24 道题分三档：入门（单表）8 题、进阶（聚合与连接）8 题、实战（子查询、窗口函数、业务统计）8 题。

练习场是**只读**的：`INSERT / UPDATE / DELETE / DROP` 一律不执行，每跑一次都从干净副本重建，改不坏。

## 五、改资料后怎么重建

抓到新的教程，或者改了题库，按顺序跑三条命令（都在 `资料库/` 目录下）：

```bash
# 1. 重建检索索引（kb.json 给测试脚本用，kb.js 给网页用）
/usr/bin/python3 脚本库/知识问答/构建知识库.py \
  --src 应用_SQL问答/教程原文:w3school \
  --src 应用_SQL问答/教程原文_MySQL:MySQL \
  --src 应用_SQL问答/教程原文_廖雪峰:廖雪峰 \
  --src 应用_SQL问答/教程原文_GitHub:jaywcjlove \
  --src 应用_SQL问答/教程原文_GitHub2:Booboo \
  --out 应用_SQL问答/data/kb.json \
  --js-out 应用_SQL问答/data/kb.js

# 2. 重生成阅读版（单文件，1500 KB）
/usr/bin/python3 脚本库/知识问答/生成阅读版.py
```

改完跑一遍自检，确认没有断链：

```bash
cd 脚本库/知识问答
env -u NODE_OPTIONS node 校验应用.js          # 资源、题号、锚点、答案分布
env -u NODE_OPTIONS node 校验题库.js          # 24 个标准答案能不能跑通
env -u NODE_OPTIONS node 校验判定.js          # 一题多解算不算对、错写法定不定得住
env -u NODE_OPTIONS node 检索自检.js /home/wsqw/wsqw_UOS/资料库/应用_SQL问答 "你的问题"
```

抓一个新站点：在 `抓取教程.py` 的 `SITES` 里加一段配置（入口页、链接正则、正文起止标记），然后 `python3 抓取教程.py 站点名`。

## 六、已知的不足

1. **MSSQL 覆盖薄弱**。微软的官方文档站点是 JS 渲染的，抓不下来，目前只有 SQL Server 函数、存储过程、数据类型对照三处提及。要给 SQL Server 补料，得手动找页面。
2. **答疑是检索式的，不是大模型**。它只会"从这几份教程里挑最相关的段落念给你听"，不会自己组织新句子、也不会推理。所以问法要贴近教程用词——问"去重"不如问"distinct"准。
3. **Booboo 那三节内容杂**，混了 mysql 命令行回显和笔记碎片，检索命中它时给出的要点质量不如其他四份。已经在过滤，但没根除。
4. **练习场只支持 SQLite 语法**。`LIMIT`、`IFNULL` 这些能用；MySQL 特有的 `SHOW`、`DESCRIBE`、`DATE_FORMAT` 不一定能用。练通用 SQL 没问题，练 MySQL 专有语法会碰壁。
5. **没有执行计划、没有性能内容**。教的是"怎么写对"，不涉及"怎么写快"。
